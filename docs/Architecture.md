# Vantillu Restaurant Architecture

## Overview
Vantillu Restaurant is a monolithic web application built with:
- **Frontend**: Next.js 14, Tailwind CSS, Framer Motion
- **Backend**: Flask (Python 3.10+), SQLAlchemy, Flask-Migrate
- **Database**: PostgreSQL (hosted on Supabase)
- **Deployment**: Vercel (Frontend), Render (Backend)

## Key Architectural Patterns

### 1. Repository Pattern
All database access is abstracted behind the Repository Pattern. The `BaseRepository` provides common methods (create, update, soft delete, fetch). Specific models extend this to add custom queries.
- `backend/repositories/base.py`
- `backend/repositories/menu_repository.py`

### 2. Concurrency & Optimistic Locking
To prevent concurrent updates from overwriting each other (e.g., two admins editing a menu item at the same time), all mutable entities have a `version` column.
- The client sends the current `version`.
- The backend checks `client_version == db_version`.
- If they match, `version` is incremented. If not, a `409 Conflict` is returned.

### 3. Idempotency
Order placements include an `Idempotency-Key` (UUID) generated by the frontend.
- If the backend receives a POST to `/api/v1/orders` with an existing idempotency key, it skips creation and returns the existing order.
- Prevents double charges on network retries.

### 4. Soft Deletes
Models include `is_deleted` (Boolean) and `deleted_at` (DateTime).
- Repositories automatically filter out `is_deleted == True` on reads.
- Deletes perform an update setting `is_deleted = True` rather than an SQL `DELETE`.

### 5. Audit Logging
A middleware in `backend/middleware/audit.py` captures POST, PUT, DELETE requests and logs them to the `audit_logs` table for compliance and debugging.
